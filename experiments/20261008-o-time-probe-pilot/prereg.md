## 1. 問い・位置づけ・claim の上限

**問い**: 1 つの凍結 qwen3:8b (think=False) の上で、同じ base・空の初期状態のエージェントに、環境が 2 日にわたって与えた観察の成功行を、
日付の札つきで状態として見せる。族の 2 エージェントは、記録の集合 ((部屋, 行動) の多重集合) が同じで、規則の列の順 (1 日目 A → 2 日目 B と、
1 日目 B → 2 日目 A) だけが違う。このとき、記録にある部屋の「今の状況」で、選択が**現在 (新しい日) の規則の向きに**、τ を超えて違うか。

- 位置づけ: 次の候補の scoping ADR §5.4 の候補 O_time (M1: 時期の評価) の具体化。現行目標 (2026-09-27「同一 base から、ペルソナごとの
  思考の分散」) を、閉集合 C で、「同じ経験の集合でも、経験の順だけで選択が分かれるか」の形で問う。統合系ではない。
- 推定量 C は、族内の選択分布 TV に対する、向きの付いた下界 (v2・G と同じ)。
- 事前の見込みの記録は無い (scoping ADR §4)。INCONCLUSIVE に終わる公算もある。それは規則による door-close の条件ではない (研究者判断として起こした)。
- claim の上限と license は §11。

## 2. 設計 (実装 = `scripts/o_time_probe_battery.py`)

### 2.1 世界と族

- 状況 = 部屋 6 つ (色の名、新語彙): crimson・violet・amber・cobalt・ivory・olive (番号 i = 0..5)。distractor は置かない (答えは状態にある)。
- 族 0 の行動 label (規則 A・B): ring_bell・open_gate・fill_jar。族 1 (規則 C・D): trim_wick・seal_crate・hang_rope。新語彙で、互いに・
  G と v2〜v5 と Stage B の語と文字 4-gram を共有せず、数字を含まない (機械検査)。
- 規則: A(x) = L0[i mod 3]、B(x) = L0[(i + 1) mod 3]。C・D は同じ形で L1。全部屋で 2 つの規則は違う行動を指し、各規則で各 label がちょうど 2 部屋。
- arm (規則の列): 族 0 = `AB` (1 日目に A、2 日目に B)・`BA` (その逆)。族 1 = `CD`・`DC`。向き: fwd = {AB, CD}、bwd = {BA, DC}。
  - w_a(x) = 新しい日 (2 日目) の規則の行動、foil_a(x) = 古い日 (1 日目) の規則の行動。族の 2 arm で w と foil が入れ替わる。
  - Ω の残り 1 つ (部屋 x の記録に無い族の label) は w でも foil でもない。
- 族の 2 状態の (部屋, 行動) の多重集合は同じ ({(x, A(x)), (x, B(x))})。違うのは各行の日付の札だけ (機械検査)。

### 2.2 曝露と aggregator (状態の生成)

- 環境は、族で共通の固定の試行 schedule を与える: 2 日にわたり、各日に各部屋で族の 3 行動を各 3 回試させる。成否はその日の規則で決まる。
  エージェントは行動しない (開ループ、エージェント自身の探索を問わない)。
- 決定的な aggregator が、日ごとに (部屋, 行動) の成否を数え、その日の中で失敗の無い成功だけを固定の文言の行に記録する。研究者は規則を書かない。
  - 日をまたいで数えない (またぐと、どの行動も成功と失敗が混じって行が残らない。test で pin)。
  - 各日の各部屋にちょうど 1 行、行動 = その日の規則、成功数 = 3 (機械検査)。状態は 12 行。

### 2.3 日付の札 (時期の担い手) と、孤立の 2 層

- 書き方 e ∈ {`asc`, `ago`}:
  - `asc` (起点から数える): 古い日 = 「1 日目」、新しい日 = 「2 日目」。新しい日の数が大きい。
  - `ago` (今から遡る): 古い日 = 「2 日前」、新しい日 = 「1 日前」。新しい日の数が小さい。
- 行の文面: 「[<札>] 条件: <部屋> の部屋 → 行動: <label> (成功 3 / 失敗 0)」。
- **層 1 (単位の中、定理 1)**: 同じ書き方の 2 arm は、行の並び・Ω の表示順・seed を共有し、各行の札の数字だけが違う
  (AB の A の行は古い日、BA の A の行は新しい日)。札の数字を伏せた prompt は 2 arm で byte 一致する (機械検査 `check_layer1`)。
- **層 2 (書き方の対、定理 2)**: 札の後ろの語 (目 / 前) を伏せると、`ago` の fwd arm の prompt は `asc` の bwd arm の prompt と一致し、
  `ago` の bwd arm は `asc` の fwd arm と一致する (どの行に数字 1 と 2 が付くかが arm の入れ替えと同じになる。機械検査 `check_layer2`)。
- **時期の担い手の選択と根拠** (実データの前に固定、scoping ADR §5.4・BL-3、user 裁定 DU-1):
  - 担い手は行ごとの日付の札にし、行の順は担い手にしない。行の順を担い手にすると「最後の行を写す」位置の方策が時期の評価と同じになる。
    札にして行の位置を族で共有すれば、位置の方策は層 1 で打ち消す。
  - 札の書き方を 2 種にし、単位の中で対にした。書き方 1 種 (例「期 1 / 期 2」) では、「大きい数を選ぶ」「数字 2 の行を選ぶ」「辞書順で大きい札を選ぶ」
    方策が時期の評価と区別できない。向きの逆な書き方を対にすると、後ろの語を読まない方策は層 2 で打ち消し合う。
  - 残るのは、後ろの語と数の組 (起点から数えるか、今から遡るか) を読む方策である。PASS の claim はここまで (§11)。
- **probe の文言** (構成概念の一部として固定): 「今の状況: <部屋> の部屋。\n次の行動から 1 つだけ選び、行動名だけを答えよ: <Ω>」。
  - 「今」は現在の位置を示すだけで、どの記録に従えとも書かない (「新しい記録に従え」と書けば指示への追従になる)。
  - probe は単位の 4 呼び出しで同一にし、書き方に依る印 (「3 日目の状況」「今日の状況」など) を入れない。入れると定理 2 の前提 (後ろの語以外の
    prompt の一致) が崩れ、「probe の数に近い札」のような字面の方策が書き方の対で打ち消さなくなる。指示文の「1 つだけ」の数字は 4 呼び出しで
    同じなので、それを読む方策も定理 2 の対象に入る (自己点検 DF-2)。
  - 状態の見出しは「これまでの経験の記録:」、system は「あなたは与えられた状況で、示された行動の中から 1 つを選ぶ。」(G・v2 と同じ、persona なし)。

### 2.4 単位・並び・Ω・seed (依存の単位、gate 2)

- **単位** u = (族 f, 部屋 x, replicate r)。単位に 4 呼び出し (2 arm × 2 書き方) を置く。本走の単位は 12R 個、呼び出しは 48R。K = 1。
  R は §7.1 の規則で選ぶ (候補 {96, 192, 288})。
- 単位ごとに 12 行の並び π_u = `default_rng([20261008, f, i, r]).permutation(12)` を引く。並べるのは slot (部屋, 行動) で、札は arm と書き方が付ける。
  4 呼び出しで共有し、単位の間では共有しない。
- Ω = 族の 3 label。表示順は族の正準順を (r + i) mod 3 だけ巡回し、4 呼び出しで共有する。R が 3 の倍数なら、各 (族, 部屋) で各 label が
  各表示位置に R/3 回来る (機械検査)。
- **decoding seed** = 20261008 + 10,000,000·g + 10,000·r + 100·i + k。g は名前空間 (本走の族 0 / 1 = 0 / 1、pilot の masked = 3 / 4、
  pilot の M0 = 5 / 6)。**単位の 4 呼び出しで共有し、単位の間では共有しない**。本走の r ∈ [0, 288)、pilot の r ∈ [300, 306)。名前空間と r の範囲は
  交わらない (機械検査)。
- K = 1 の理由: G と同じ (セル内の決定性が高く、独立な単位を増やす方が τ 判定の天井 (§5.3) を下げる)。

### 2.5 実行条件の非漏洩と byte 予算

- 非漏洩 (機械検査): prompt の ASCII の語は部屋・label・数字 (札・成功数・「1 つだけ」) だけで、arm 名・規則名・書き方の名・向きの名を入れない。
- byte 予算: 描画 prompt の最大は約 1.2 KB。上限 3,000 + template 64 + num_predict 32 ≤ num_ctx 4,096 (token 数 ≤ UTF-8 byte 数) で、
  切り詰めが起こりえないことを静的に保証する (本走・masked・M0 の全 prompt、r < 288 で検査)。

### 2.6 battery の機械検査 (`battery_violations`、判定の前に必ず通す)

語彙の 4-gram と数字 / 規則 (全部屋で相異・各 label 2 部屋・w と foil と残りの相異) / aggregator と日ごとの規則・曝露 schedule の族内一致 /
多重集合の族内一致と各日の label の頻度 2/2/2 / 札 (書き方の中で数字だけが違い、書き方の間で後ろの語と数字の向きだけが違う) /
**定理 1 の前提** (札の数字を伏せた 2 arm の prompt 全体の一致) / **定理 2 の前提** (後ろの語を伏せた書き方の対の prompt 全体の一致。
どちらも system・role・message の件数を含めて比べる。Codex HIGH-1) / 非漏洩 / 表示位置の均衡 /
byte 予算 / masked の状態 (札の数字だけを伏せ、同じ書き方の 2 arm で同一) / M0 の状態 (新しい日の行だけ、2 arm は label だけが違う) /
seed の名前空間の分離。

## 3. estimand (v2・G と同じ式、単位を書き方の対にした)

- セルの得点 s_{a,e,u} = [w_a を選んだ] − [foil_a を選んだ] (K = 1)。⊥・Ω の残り (記録に無い行動)・語彙内の Ω 外は 0。
- d_{u,e} = (s_{fwd,e,u} + s_{bwd,e,u}) / 2、**D_u = (d_{u,asc} + d_{u,ago}) / 2**、**C = mean_u D_u**。
  - 完全な時期の評価 (新しい日に従う) = 1。札の数字を見ない方策 = 0 (定理 1)。後ろの語を読まない方策 = 0 (定理 2)。古い日に従う = −1。
- 成分 = 向き × 書き方の 4 つ (族はまとめる): (fwd, asc)・(fwd, ago)・(bwd, asc)・(bwd, ago) の s の平均。
- 記述 (判定に使わない): 記録に無い行動を選んだ率・書き方ごとの C。

## 4. 実行条件・parse・記録 (凍結。driver は本登録の範囲外で、仕様だけ登録する)

- model `qwen3:8b`、think=False、temperature 0.7、top_p 0.8、repeat_penalty 1.0、num_ctx 4096、num_predict 32、options.seed を明示 (G・v2 と同じ着座)。
- **meta.json** = `{"request": request_meta(), "observed": {"model_digest", "ollama_version", "template_sha256"}}`。
  request が凍結値と違えば INVALID_SCORER。本走の observed が pilot の observed と違えば INVALID_SCORER。
- **記録の schema** (1 行 1 JSON object、欄は過不足なく): `call_index` / `replicate` / `k` / `seed` (int、bool を int に読み替えない)、
  `arm` / `encoding` / `probe_id` / `prompt_sha256` (str)、`raw` / `parsed` (str または null)。`probe_id` = 「x<部屋の番号>」。違反は例外で止めず INVALID_SCORER。
  記録は改行だけで行に割る (`splitlines()` は U+2028 などでも割るので使わない)。
- 呼び出し順 (driver への要件、判定は call_index の一意性だけを検査する): 単位の順に、単位の 4 呼び出しを続けて。
- **parse** (`parse_choice`、G・v2 と同じ規則を新語彙で、test で pin): NFKC → 小文字化 → 閉じた think ブロックを除去 (閉じない tag が残れば ⊥) →
  6 label のちょうど 1 種を単語境界で含めばその label (`ring bell`・`ring-bell` も同じ label)。0 種・2 種以上は ⊥。
  transport 失敗 (同じ seed で 3 回まで再送して解けないもの) は `raw = null` を記録し、run 全体を `status=not_computed` にする (⊥ にしない)。
- 結果の JSON は LF で書く (G prereg BL-3)。

## 5. 判定 rule (verdict は `docs/research-positioning.md` §8 の 5 語のみ。実装 = `scripts/o_time_probe_scorer.py`)

評価順に適用し、最初に当たったものを verdict とする。**τ = 0.30**・**α = 0.05** (v2・G の literal を継ぐ)。

1. **INVALID_SCORER** — certification (`results/certification.json`) が無い・全 KILLED でない・記録 sha256 が現在のコードと一致しない /
   battery の機械検査 (§2.6) の違反 / fixture gate (§6) の違反 / meta の違反 (§4) / 記録の schema・構造の違反 (重複・grid 外・seed・prompt・parse・call_index)。
2. **計算しない** (`status=not_computed`、verdict なし) — transport 失敗の記録がある、または行が欠ける。
3. **INVALID_TASK_BATTERY** — lever 4 arm のいずれかの ⊥ 率 (書き方と単位をまとめる) > min(0.2, pilot の masked の最大 ⊥ 率 + 0.05) (envelope、§8.3)、
   または族内の ⊥ 率差 ≥ τ/4。
4. **PASS** — E⁺ ≥ 1/α **かつ** 4 成分 (向き × 書き方) の標本平均がすべて > 0。
   - 成分の条件は標本平均の符号の条件で、成分ごとの推論ではない。片方の書き方 (または向き) にだけ真の効果があっても PASS しうる
     (Codex HIGH-2 の反例: asc の 2 arm は常に新しい日、ago の 2 arm は独立に ±1 を等確率なら、ago の真の対比は 0 だが、
     R = 288 で ago の 2 成分の標本平均がともに正になる確率は約 0.243 で、そのとき C > 0.5 で PASS する)。claim は §11 で限る。
5. **NO_GO_EFFECT_ABSENT** — E⁻ ≥ 1/α。
6. **INCONCLUSIVE_UNDERPOWERED** — それ以外。

### 5.1 τ 判定 (G prereg §5.1 を継ぐ)

- E⁺ = mean_{λ∈Λ⁺} Π_u (1 + λ(D_u − τ))、Λ⁺ = {j/4 · 1/(1+τ) : j = 1..4}。
- E⁻ = mean_{μ∈Λ⁻} Π_u (1 + μ(τ − D_u))、Λ⁻ = {j/4 · 1/(1−τ) : j = 1..4}。
- E⁰ = 平均 > 0 の同型の e-value (記述報告だけ。判定に使わない。「τ 未満の正の効果」と読まない)。

### 5.2 有効性 (gate 2 の前提の監査。計測台 §2.1.1 の 4 項目)

- **推論の対象**: 主な推論は、**固定した prompt の schedule 全体** (並び・表示順・書き方・seed) に条件付けた、decoding の抽出についての推論である。
  帰無は「単位平均の平均 (1/n) Σ_u μ_u ≤ τ」、μ_u = その単位の 4 prompt での E[D_u] (期待値は decoding について)。
  新しい layout・新しい項目への一般化は、この推論から言わない (§11)。
- **定理**: 単位の D が独立で [−1, 1] に有界なら、帰無の下で固定の λ について E[Π_u(1 + λ(D_u − τ))] = Π_u(1 + λ(μ_u − τ)) ≤ (1 + λ(μ̄ − τ))^n ≤ 1
  (各因子は λ ≤ 1/(1+τ) で非負。AM-GM)。混合も同じ。Markov で P(E⁺ ≥ 1/α) ≤ α。NO_GO 枝も同じ (μ ≤ 1/(1−τ))。
  2 枝は同時に立たない (log の凹性。test で pin)。対称性・同分布・交換可能性を仮定しない。保証は枝ごとの α である。
  4 成分の条件・⊥ gate との積集合は PASS の size を増やさない。
- **依存の単位**: 単位 = (族, 部屋, r)。単位の 4 呼び出しは並び・表示順・seed を共有して強く依存するので、その平均 D_u を 1 つの独立の単位にする
  (scoping ADR §6 gate 2・DC2-3: 対の 2 値を 2 つの独立の因子として掛けると e-value の証明が使えない)。単位の間では seed も並びも共有しない。
  単位の間の独立は、別の seed の呼び出しが独立な抽出であるという理想化 (v2〜v5・G と同じ) に依る。
- **相殺の条件** (機械検査、§2.6): 多重集合の族内一致・曝露 schedule の一致・定理 1 と定理 2 の前提の byte 一致 (system・role・全 message を含む prompt 全体)・表示位置の均衡・seed の共有と分離。
- **鋭い null**: 札の数字を見ない方策 (prompt の札の数字以外と seed の関数) は、どの単位・どの書き方でも d = 0 (定理 1)。後ろの語を読まない方策は
  d_ago = −d_asc で D = 0 (定理 2)。どちらも帰無の 1 点で、上の定理はそれより広い帰無の領域を覆う。決定的な decode の理想化の下で単位ごとに厳密、
  非決定性の残りは期待値で 0 (G と同じ理想化。null pilot の masked で不一致率を記述する、§8)。

### 5.3 判定の天井 (雑音ゼロでも要る大きさ)

有界の平均の検定は、帰無 {m を確率 p、−1 を確率 1 − p} を排除できないので、全単位が m でも m ≥ (1+τ)·α^(−1/n) − 1 が要る
(n = 1,152: 0.303、n = 2,304: 0.302、n = 3,456: 0.301)。

## 6. fixture 表 (登録した方策、L4。実装 = `scripts/o_time_probe_fixtures.py`、出力 `results/fixture_table.json`)

- モデルが登録した方策に完全に従ったときの C を、凍結した設計 (全単位・本走の並び・表示順・書き方の対) の上で厳密に計算する。

  判定の INVALID_SCORER にも組み込む。
- **定理 1 (札の数字を見ない方策)**: 同じ書き方の 2 arm は、prompt が札の数字だけ違い (§2.3)、seed が同じである (§2.4)。よって、札の数字を除いた
  prompt と seed の関数である方策は、2 arm で同じ label L を選ぶ。L が A(x) なら s_fwd = −1・s_bwd = +1、B(x) なら逆、それ以外なら 0。**どの単位・
  どの書き方でも d = 0**。写し (条件の合う行の最初・最後)・位置・最多・行数・label × 位置・隣の行の写し・label の事前傾向は、すべてこれに入る。
- **定理 2 (後ろの語を読まない方策)**: 後ろの語を伏せると、`ago` の fwd arm の prompt = `asc` の bwd arm の prompt、`ago` の bwd = `asc` の fwd
  (§2.3)。4 呼び出しは seed を共有する。よって後ろの語を読まない決定的な方策 (札の数字・字面・位置・頻度の任意の関数) は、
  d_ago = (cat_fwd(L₁) + cat_bwd(L₂))/2 = −(cat_bwd(L₁) + cat_fwd(L₂))/2 = −d_asc (cat_fwd = −cat_bwd)。**どの単位でも D = 0**。
  - 前提: 対の 4 呼び出しで、札の後ろの語以外の prompt 全体 (probe・選択肢の表示・system) と seed が一致すること・対を等しい重みで平均すること・
    対の欠けが無いこと (欠けは not_computed)。
- 登録した方策 29 種 (`registered_policies`):
  - `tag_blind` (定理 1): 条件の合う行の最初 / 最後・最初 / 最後の行・表示の先頭 / 末尾・行数 mod 3・label × 位置・隣の行の写し・記録に無い行動・
    label の辞書順 (最小 / 最大)・最多の label (同点 {最初, 最後})。
  - `tag_relative` (札の入れ替えに不変): 最初 / 最後の行と同じ札の行・先頭 3 行で多い札の行・末尾 5 行で少ない札の行。
  - `tag_literal` (定理 2): 大きい数 / 小さい数・数字 "2" / "1"・辞書順で大きい / 小さい札・札の長さ (同点 {最初, 最後})・
    大きい数の行が後に表示されていればそれ (fallback {記録に無い行動, 条件の合う最初の行})・数 + 表示位置。
- 結果 (本走の並び、R ∈ {96, 192, 288}): **29 方策のすべてで C = 0** (厳密)。`tag_literal` の方策は書き方ごとには C_asc = ±1 / C_ago = ∓1 などで、
  対の中で打ち消す (例: 大きい数 C_asc = 1・C_ago = −1、大きい数が後なら記録に無い行動 0.5 / −0.5)。
  - 陽性対照 (gate の対象外): 新しい日に従う C = +1・古い日に従う −1・asc でだけ新しい日に従う (ago は条件の合う最初の行) +0.5 (C_asc 1・C_ago 0)。
  - test は、札の数字を伏せた文脈の任意の hash 関数の方策が単位ごとに d = 0、後ろの語を伏せた文脈の任意の hash 関数の方策が単位ごとに
    d_ago = −d_asc であることも確かめる (乱択の方策 3 種ずつ)。
- 限界: 定理 1・2 の対象外は、後ろの語 (目 / 前) と数の組を読む方策である。その中には時期の意味の評価のほかに、「目なら大きい数、前なら小さい数」を
  意味を理解せずに対応させる方策も入りうる (区別できない)。claim は「後ろの語を読まない方策と、登録した方策では説明できない」までで、
  「時間の概念の理解」は言わない (§11)。

## 7. 見取り図 (gate 4、判定に使わない。実装 = `scripts/o_time_probe_sim.py`、出力 `results/sketch.json`)

### 7.1 模型・形・規則 (実データ前に固定)

- **生成の模型**: セル = (単位, 書き方, arm)、K = 1。⊥ は確率 b。残りの質量で、確率 |λ| で w (λ > 0) か foil (λ < 0) を選び、それ以外は

- **形** (scoping ADR §5.2 の型を本登録の単位で書いたもの、12 形):

  4 **時系列の表示でだけ評価** (その部屋の 2 行が古い順に表示される arm でだけ。到達上限 (1 − b)·F。F は base と凍結した並びで決まり、uniform で 0.5) / 5 全か無か (セル・単位・arm × 単位・項目 = (族, 部屋)

  対数オッズの形は base = label_skew の 6 点。
- **回数**: power と帯の点は 2,000 回、size の点は 10,000 回、各 2 seed (20261008・20261009)。power と帯は 2 seed の平均、size は大きい方。
- **size の上限と MC の採否を別の数にする** (計測台 §4.3、G prereg §7.1 の型): 上限 = α (§5.2 の定理による真の size の上限)。MC の採否: 棄却の数 X について、
  合格は X ≤ x、棄却は X ≥ x + 1。x は P(X > x) ≤ 0.01 / G を満たす最小の整数 (X ~ Binomial(N, α)、N = 10⁴、G = その R の size の点の数 × seed 数)。
  誤棄却の族全体の率を 0.01 以下に抑える。誤採用は定理が防ぐ。
- **R の選定規則** (scoping ADR §7 の読み 5): 候補 {96, 192, 288} (単位 1,152 / 2,304 / 3,456、呼び出し 4,608 / 9,216 / 13,824)。
  次の 4 条件をすべて満たす候補のうち**最大**の R を R_MAIN とする (G の DU-1 の趣旨: 打ち止め (c) の下で INCONCLUSIVE は回し直せないので、

  3. size の点 (境界・弱い null・二点の極値) × 攪乱点で、両枝の棄却の数が合格 (X ≤ x)。

### 7.3 読み (判定ではない。凍結の可否・有効にする枝・claim を限る範囲だけを決める)

1. **最も有利な行は door-close でない**: 一様 sd 0.05 (uniform・⊥ 0・crn) の power 0.8 の境目は E[C] 0.339 (R = 288)、到達上限は 1.0。
   18 攪乱点のすべてで P(PASS | 2τ) = 1.000・P(NO_GO | 0) = 1.000 (表 2)。
2. **選定 = R_MAIN 288** (候補 {96, 192, 288}、§7.1 の規則と逸脱の記録 1・2)。R = 96・192 は条件 4 だけが不合格 (帯の決着しない確率の最悪
   0.433・0.227)。R = 288 は条件 4 の 4 攪乱点で最悪 0.120 (τ − 0.05) / 0.001 (τ + 0.05)。本走は 13,824 呼び出し (G の本走の約 8 倍、
   G の実測 約 4.6 呼び出し / 秒なら約 50 分)。
3. **両枝を有効にする**: 境界 E[C] = τ の全形と帰無の領域 (弱い null・二点の極値・逆向き・項目の全か無か) で、両枝の size の最悪値は
   0.0035 (R = 96)・0.0028 (192)・0.0016 (288) で、MC の採否の閾値 0.0596 と上限 α = 0.05 の内側だった (表 5・表 6)。§5.2 の定理が覆う。
   NO_GO の枝を外さず、claim を形で限らない (NO_GO の claim は §11 の上限まで)。
4. **R = 288 の境目** (表 3、P(PASS) が 0.8 を越える点 / P(NO_GO) が 0.8 を下回る点、有利 / 不利): 一様 0.339〜0.342 / 0.252〜0.255、
   セルの全か無か 0.320 / 0.333、単位の全か無か 0.341 / 0.345、時系列の表示でだけ評価 0.340 / 0.338 (到達上限 0.500 / 0.448)、
   対数オッズ 0.424 / 0.393、逆向き 1/6 で 0.371 / 0.367。τ の近くで決着しにくい帯は狭い (一様で E[C] 0.252〜0.342 の間)。
5. **届かない形・PASS しにくい形**:
   - 部屋の 1/3 にだけ出る効果は到達上限 0.333 で、power 0.8 に届かない (INCONCLUSIVE か NO_GO)。
   - **書き方の集中 (asc だけ)** は、有利な攪乱点 (crn) では E[C] 0.3〜0.5 で P(PASS) = 0 (表 4)。crn では ago の 2 arm が同じ label を選び、
     ago の 2 成分の標本平均が打ち消すので、4 成分 > 0 を満たさない。結合が独立に近いと PASS しうる (§5 の Codex HIGH-2 の反例)。
     claim は「観測した 4 成分の標本平均が正」まで (§11)。
   - 診断用 (表 2 の右の 2 列): label_skew の crn の帯の決着しない確率は R = 288 で 0.195 / 0.265。部屋と label の強い事前の結び付きが一方の
     規則に揃うと、τ の近くで INCONCLUSIVE になりやすい (DD-5 の成分の条件による)。
6. **模擬の健全性**: 全行・全 seed で、実現した C と目標の差は最大 0.0009 (sweep も 0.0009)。時系列の表示でだけ評価する形は、凍結した並びの上の
   係数で較正した (§7.1)。
7. **読みの限界**: power の値は混合の仮定と模型の上の値で、実際の効果の形が模型の外 (例: layout や書き方に強く依る全か無か) なら下がる。
   実の雑音は null pilot (§8) の spike-in で、R_MAIN について条件付きで見る。size は模型に依らない (定理)。結合は代表的な 3 つでだけ見た。
   帯 (条件 4) は crn の uniform・position_skew の 4 攪乱点で見た (§7.1)。

- masked は時期の情報を持たない。状態を読む雑音 (行の label の写し・位置の偏り) は含む。決定的な decode なら同じ書き方の 2 arm の出力が一致し、
  null の C は単位ごとに 0 になる。null の C は観測値として spike-in の較正に使い、0 であることを仮定しない。
- pilot の r・seed は本走と交わらない (機械検査)。**pilot の記録は本走の verdict に使わない** (資格と確認の分離)。
- **時期の語義の確認** (「2 日前と 1 日前のどちらが新しいか」) **は置かない** (scoping ADR §6 gate 3・DC-5 の型: 本効果を先に選別する gate になる)。

### 8.2 機械判定 (第 1 段で凍結。順に適用)

1. STOP (records): certification・meta・schema・構造の違反、または見取り図が R を選ばなかった。
2. not_computed: transport 失敗・欠け。
3. **STOP (M0)**: M0 の腕が、**凍結した PASS の規則** (pilot の 72 単位で E⁺ ≥ 1/α かつ 4 成分 > 0) を通らない。
   - 保守的な運用規則で、構成概念 (時期の評価) の確認ではない。答えを一意に書いた状態で τ を越える lookup すら示せない pipeline では M1 を問わない。
   - 閾値を新しく作らず、凍結した判定の機械を使う (user 裁定 DU-1 の採用案)。
4. **STOP (envelope)**: masked の arm の ⊥ 率 > 0.2、または族内の ⊥ 率差 ≥ τ/4。
5. **spike-in の OC** (見取り図が選んだ R_MAIN で): 次をすべて満たせば **GO**。満たさなければ **STOP (power、door-close)**。
   - P(PASS | E[C] = 2τ) ≥ 0.8、P(NO_GO | E[C] = 0) ≥ 0.8、P(PASS | τ)・P(NO_GO | τ) が合格 (率 ≤ x / N、N = 2,000、点の数 2)、既知量への較正 (下) が成り立つ。
     5 条件のそれぞれを単独で破る test と変異がある。
   - OC の ⊥ gate は、本走と同じ上限 min(0.2, pilot の masked の最大 ⊥ 率 + 0.05) を使う。
- 記述 (判定に使わない): masked の同じ書き方の 2 arm (同じ prompt・seed) の出力の不一致率 (決定性の理想化の監査)・M0 の C・記録に無い行動の率。
- 出力 (`results/pilot/gate.json`) は、本走の判定が読む値 (GO と R・masked の最大 ⊥ 率・observed) と、入力 (記録・meta・certification・見取り図) の sha256 を持つ。
- driver は pilot の provenance (`results/pilot/provenance.json`) に、自分の sha256 と、自分が書いた記録・meta の sha256 (`driver_sha256`・`records_sha256`・
  `meta_sha256`) を記録する。第 2 段は、3 つとも現在のファイルと一致することを要求する。

### 8.3 spike-in の契約 (計測台 §4.1 の 6 項目)

- **条件付き OC**: OC は「この null 記録に条件付けた値」で、母集団への保証ではない。size は §5.2 の定理で守られ、pilot に依らない。
- **再標本化の単位と依存構造**: 単位 (族, 部屋, r) を、(族, 部屋, 表示の回転) の層ごとに本走の割付数 (R/3) だけ復元抽出する
  (単位の中の 2 arm × 2 書き方の結合と、本走の表示位置の割付を保つ)。pilot の r を 6 個にして、各層に 2 単位を置いた。
- **既知量への較正**: masked の記録の上で、⊥ でないセルを確率 λ で w (目標が null の C より小さければ foil) に置き換える。
  λ = (目標 − C_null) / (1 − b̂ − C_null) (foil の向きは対称の式)。注入の後に、実現した平均が目標から 0.01 以内であることを確かめる (外れたら OC を不合格)。
- **pilot の不確実性**: 外側の再標本化はしない。理由: size は定理で守られ、pilot の不確実性は power (決着しない率) にだけ効く。OC を条件付きと書く。
- **選定の評価**: 注入法と envelope は実データ前に固定した。R は見取り図の規則で決まり、pilot は R_MAIN の合否だけを見る (選定の自由度は無い)。
- **確認の実走との分離**: pilot の記録 (r 300〜305、別の seed の名前空間) を本走の verdict に使わない。
- **混合の仮定**: 効果を null の挙動に重なる混合と仮定する。効果が雑音の構造を変える場合は、§7 の見取り図 (対数オッズの形・3 結合) で別に見る。
- **envelope**: OC は pilot の雑音に条件付く。本走の arm ごとの ⊥ 率の上限を min(0.2, pilot の masked の最大 ⊥ 率 + 0.05) とし、外れたら INVALID_TASK_BATTERY。

## 9. 凍結と実走の手順 (それぞれ別の user 裁定)

### 9.1 第 1 段 `PILOT-FROZEN`

### 9.2 null pilot (第 1 段の後、user 裁定で GPU を許可した後)

2. `bash experiments/20261008-o-time-probe-pilot/run.sh pilot`: manifest の照合 (stage pilot) → 機械判定を 2 回計算して byte 一致 → `results/pilot/gate.json`。
3. STOP なら本走を起こさない (打ち止め (c) では INVALID と同じ扱い、§0)。

### 9.3 第 2 段 `FROZEN` (確認実験)

1. 第 2 段の照合 (`--verify --stage main`、manifest が機械的に行う):
   - 第 1 段の封印: `manifest.json` があり、prereg は status 行以外 (`prereg_body_sha256`)、他の対象は sha256 が封印時と同じ。
   - pilot: 凍結した機械判定を記録から再計算し、GO・R・masked の最大 ⊥ 率・observed が `gate.json` と一致する。R が見取り図の選定と一致する。
     入力の sha256 が現在の記録と一致する。provenance の driver・記録・meta の sha256 が現在のファイルと一致する。
   - driver の certification が契約を満たす (各行が一意の label・KILLED・空でない期待診断・期待診断のどれかで実際に落ちた、登録変異の集合 = driver の harness の
     `MUTANTS`、meta-test が `META_CASES` と一対一で各ケースの期待集合が実際の失敗に含まれる、driver・driver の test・harness の sha256)。
2. prereg の status を `**FROZEN**` にし、`--write --stage main` で `manifest_main.json` を書く。対象 = 第 1 段の対象 + 固定した証拠の集合
   (`manifest.json`・pilot の記録・meta・provenance・機械判定の出力・driver・driver の harness・driver の test・driver の certification)。
3. `--verify --stage main` が `MANIFEST OK (stage main)` を出すことを確かめ、commit する。

### 9.4 本走 (第 2 段の後、さらに別の user 裁定で GPU を許可した後)

1. driver が §2 の設計・§4 の条件で lever 4 arm × 2 書き方を呼ぶ (R = R_MAIN、pilot と同じ実行環境)。途中で R・prompt・parse を変えない。
2. `bash experiments/20261008-o-time-probe-pilot/run.sh main`: manifest の照合 (stage main) → 判定を 2 回計算して byte 一致 → `results/run/results.json`。
3. certification は凍結時のものを読むだけで、実走後に変異 harness を回し直さない。凍結した本走の回し直しはしない (verdict の置き換えになる)。

  - 判定は 3 通りに分けて報告する: 対照 (無変異) が落ちた → harness を止める / 変異が捕まらなかった (SURVIVED) / 落ちたが理由が違う

  照合に使う登録 (R・形・攪乱点・格子・回数・seed) と計算 (到達上限・二項の閾値・境目の補間) は sim から導かずに manifest に書く。二項の閾値は
