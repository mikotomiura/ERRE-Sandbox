# Issue 004: W-N1 到達性 witness + W-N3 outbound ownership witness
verify_level: recheck

## Goal
「配線が届いた」を **boolean / count だけ**で述べる witness を実装する。
`verdict` は明示 `None`。effect / divergence / detectability / floor / scorer は emit しない。

## Background
- **W-N1**（PR #89 HIGH-2 の継承）: seam 粒度は非一様。
  `perturbation` / `perception` / `capture` は **per-correlation**、
  `firing_summary` / `same_tick_envelope_observed` は **tick-level co-occurrence** であって
  per-correlation causation ではない（correlation-id は outbound wire protocol に到達しない）。
- **Codex M-2**: 到達性の母集団は **injected のみ**。unknown target は `rejected` count、
  overflow は `dropped` count として**別枠**に置く。
- **Codex H-2**: broadcast 側 ledger を `WorldRuntime.drain_envelopes()` の**事後観測で取らない**。
  gateway `_broadcaster` が同じ queue を `recv_envelope()` で消費するので race-dependent になる。
  **gateway が実際に fan-out したものを記録する session** から取る（gateway は無改変）。
- **Codex H-3**: dialog scheduler は `dialog_initiate` / `dialog_turn` / `dialog_close` を
  `world.inject_envelope` 経由で broadcast queue に入れる **正当な第二の生産者**。
  society へ 3 本目の kwarg を足さずに wrap する手段が無いので、
  **gate は cognition kind 限定**（`move` / `speech` / `animation` / `agent_update`）に縮小し、
  `dialog_*` は **plain count の annotation（非 gate）** に置く。除外理由をコードに明記する。
- live root はそもそも駆動ループ本体を持たず outbound に触れないので、
  `inject_envelope` 非呼び出しを spy で pin すれば cognition 側の単一 owner 性は担保される。

## Scope
### In
- `society_wiring_reachability_summary(...)`:
  - per-agent / per-correlation の seam boolean（`injected` 母集団のみ）。
  - `rejected_count` / `dropped_count` / `injected_count` の plain count。
  - `no_double_send`（cognition kind 限定の多重集合一致）。
  - `dialog_envelope_counts`（annotation、非 gate）。
  - `verdict: None` と、**reachability is not causation** / seam 粒度非一様 / dialog 除外理由を
    書いた `note` 文字列。
- consume 側 ledger の収集口（gateway 無改変で fan-out 先を記録する session）。
- live root が `inject_envelope` を呼ばないことの spy。
### Out
- ミラー witness（I5）、Plane G（I6）、firing summary の per-agent 化（I6 の annotation で扱う）。

## Execution Result

**land したのは配線 (construction) であって aha / emergence / effect ではない。**
本 issue が足したのは「配線がどの seam まで届いたか」を boolean と count だけで述べる
witness と、その入力を取るための収集口・spy。到達性は因果ではない。
「N 体が live で相互作用した」= **配線到達性の boolean** であって社会的創発の実証ではない。
wall-clock real-time session ではない境界 (scripted in-process 摂動列 + `ManualClock`) も不変。

### 実装 (すべて Allowed Files 内、`gateway.py` / `society.py` / organ は無改変)

`src/erre_sandbox/integration/embodied/society_live_loop.py` に追記:

1. **`society_wiring_reachability_summary(run, *, broadcast_envelope_kinds) -> dict[str, Any]`**
   — pure な boolean/count witness。返り値キーは
   `per_correlation_id` / `all_correlation_ids_reach_all_seams` / `injected_count` /
   `rejected_count` / `dropped_count` / `cognition_envelope_kinds_enqueued` /
   `cognition_envelope_kinds_consumed` / `no_double_send` / `dialog_envelope_counts` /
   `verdict` (= 明示 `None`) / `note` の 11 個のみ。
   effect / divergence / floor / score / detectability / magnitude / aha を名乗るキーは無い。
   - **母集団は `injected` のみ** (Codex M-2)。`rejected` / `dropped` は plain count で別枠。
   - seam 粒度は **3 段で非一様**、`note` に明記:
     - per-correlation = `perturbation` / `perception` / `target_agent_routing`
     - per (agent, window) = `capture`
     - tick-level co-occurrence = `same_tick_cognition_stepped` / `same_tick_envelope_observed`
       (同一 tick の全摂動が同じ値を読む = by construction、over-count ではない)
2. **`SocietyBroadcastLedger`** — consume 側 ledger。`Registry.reserve_slot` (public) で
   unbounded (`maxsize=0`) の記録用 queue を `app.state.registry` に登録し、
   `Registry.fan_out` が実際に push したものを push 時点で記録する。
   事後 `WorldRuntime.drain_envelopes()` は一切使わない (Codex H-2)。
3. **`society_live_gateway_lifespan_serve()`** — `app.router.lifespan_context(app)` を
   同一 event loop で回す `gateway_serve`。gateway の `_broadcaster` が本当に走るので
   consume 側が非 vacuous になる。`TestClient` は別スレッド別ループなので不採用。
4. **`spy_inject_envelope_callers()`** — `WorldRuntime.inject_envelope` の呼び出し元
   module 名を記録する context manager (class 属性 patch。dialog scheduler が attach 時に
   bound method を捕まえるので instance patch では見えないため)。
5. **`SocietyInjectedPerturbation.routed_agent_id`** を additive 追加。
   `world_perturbation_to_perception` は `agent_id` を `msg.target_agent_id` から無条件に
   写すので、`msg.target_agent_id == observation.agent_id` **だけでは恒真**になる。
   router が実際にどの agent の bucket から出したかを記録して初めて
   `target_agent_routing` が N 体 routing の実 witness になる (AC1)。
6. **`supervise_society_live_loop(..., broadcast_ledger=None)`** を additive 追加
   (新規モジュール内で完結、`society.py` の kwarg は 2 本のまま = **Stop S1 非該当**)。
   readiness hook 内で `attach` (fan-out 開始前)、drive 完了後 serve cancel の**前**に
   `quiesce` (broadcaster が別 task なので最終 window 分がまだ in-flight)。
   既定 `None` で既存 18 test は無改変で緑。

### 除外集合 (コードに明記)

- gate 対象 = `COGNITION_ENVELOPE_KINDS` = `agent_update` / `animation` / `move` / `speech`
- `DIALOG_ENVELOPE_KINDS` = `dialog_initiate` / `dialog_turn` / `dialog_close`
  → **plain count annotation、gate に含めない** (Codex H-3: dialog sink は
  `run_society_loop` 内部で `world.inject_envelope` に固定されており、3 本目の kwarg 無しには
  wrap できない。完全版 = `dialog_envelope_sink` は別 ADR へ defer)
- `EXCLUDED_ENVELOPE_KINDS` = `handshake` / `world_tick` (定期 liveness heartbeat もこの kind) /
  `world_layout` / `error` / `reasoning_trace` / `reflection_event` + dialog 3 種

### I5 / I6 への申し送り

- `SocietyInjectedPerturbation` に `routed_agent_id` が増えたので、I6 の Plane G
  `ledger_observation_factories` は **routed 側でグルーピングする**こと
  (`observation.agent_id` ではなく `routed_agent_id` が「どの window に入ったか」の SSOT)。
- `supervise_society_live_loop(broadcast_ledger=...)` は attach/quiesce を内部で行う。
  I6 が別の consume 側記録を足すなら同じ 2 点 (fan-out 前 attach / serve cancel 前 quiesce) を守る。
- `society_live_gateway_lifespan_serve()` は port を bind しない。実 Godot 接続は保証範囲外
  (`decisions.md` DA-SLC-6 (b))。実 WS end-to-end が要るなら別 ADR。
- `spy_inject_envelope_callers()` は **class 属性 patch** なので、
  `run_society_loop` 開始より前に入らないと dialog sink の bound method を捕まえられない。
- **firing summary の per-agent 化 (I6) と ミラー witness (I5) は本 issue の Out**。
  本 witness は `two_phase_firing_summary` を一切読まない (society 版が未整備のため
  tick-level seam を committed decision 側から取っている)。I6 で足すなら
  `verdict: None` と非 gate annotation の規律を継承すること。
