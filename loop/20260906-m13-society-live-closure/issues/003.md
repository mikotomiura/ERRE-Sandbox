# Issue 003: 閉包 composition root + supervisor（N 体 live セッションが起動して回る）
verify_level: recheck

## Goal
`society_live_loop.py` を **閉包専用の薄い composition root** として完成させ、
knob-on + `self_other_enabled=True` + router factories で **`run_society_loop` をそのまま live の
駆動ループとして回す**。`on_runtime_ready` で得た `WorldRuntime` を gateway に渡し、
gateway serve と駆動を**同一 event loop の `TaskGroup`** で監督する。

## Background
- ADR §1: **駆動ループを二本のままにせず一本にする**。live 側は独自 scheduler を持たない。
- **Codex H-1**: gateway app の構築・起動は `on_runtime_ready` の中で完了させ、その await が
  返ってから最初の window に入る（readiness barrier）。
- 既存前例 = `live_loop.supervise_live_loop`（gateway serve + driven を同一 `TaskGroup` で監督、
  driven 完了で serve task を cancel、`CancelledError` を suppress）。`gateway_serve` は
  caller 注入（production は uvicorn、test は軽量 stub）。
- 事前登録定数: **N=3**（`society_live.py` の `a_kant` / `a_nietzsche` / `a_rikyu`）、
  **`n_cognition_ticks=12`**（`SOCIETY_LIVE_N_COGNITION_TICKS`）。
- LLM 面は `society_live.run_society_live_capture` と同じ `ThinkOffChatClient` →
  `RecordReplayChatClient` の包み方を**再利用**（`society_live.py` は無改変）。

## Scope

- `build_society_live_world(...)` — agent_states / personas / store / embedding / llms /

- 実 Godot（Out）。UI trigger（Out。PR #89 I5 の `send_perturbation` は landed 済）。

## Execution Result

**実装 (`src/erre_sandbox/integration/embodied/society_live_loop.py` に追記)**:

- `SocietyLiveWorldInput`（frozen dataclass）+ `build_society_live_world(...)` —
  agent_states / personas / store / embedding / llms / router / knob /
  inbound_sink を束ねる**入力バンドルのみ**の construction。`WorldRuntime` は
  一切構築しない（ADR §1 の核）。`society_live.py` の固定 constructors
  (`society_live_agent_states` / `society_live_personas`) を無改変のまま再利用し、
  `run_society_live_capture` の `RecordReplayChatClient(inner=ThinkOffChatClient(...))`
  という包み方だけを再現（同関数自体は新 kwarg 2 本を素通ししないため呼べない）。
- `SocietyLiveRunResult`（frozen dataclass: `result: SocietyRunResult` /
  `ledger: SocietyInboundLedger` / `runtime: WorldRuntime`）+
  `run_society_live_loop(...)` — `run_society_loop(..., two_phase_knob=world.knob,
  on_runtime_ready=<internal hook>, observation_factories=router.observation_factories(...),
  self_other_enabled=True, n_cognition_ticks=SOCIETY_LIVE_N_COGNITION_TICKS)` を
  そのまま呼ぶ薄い pass-through。内部フックが `on_runtime_ready` が受け取った
  `WorldRuntime` を自分の戻り値用に捕捉しつつ、caller 供給の `on_runtime_ready`
  （sync/async 両対応）へもそのまま転送する。
- `supervise_society_live_loop(...)` — `live_loop.supervise_live_loop` と同型の
  同一 event loop `asyncio.TaskGroup` 監督。**1 点だけ意図的に形が異なる**:
  `gateway_serve` は zero-arg でなく `Callable[[FastAPI], Coroutine[Any, Any, None]]`
  （構築済み FastAPI app を受け取る 1 引数）。理由 = `build_society_live_world` が
  runtime を作らない設計制約上、`make_app(runtime=..., inbound_sink=...)` は
  `on_runtime_ready` の中でしか呼べず（runtime がそれまで存在しない）、
  live_loop 側のように呼び出し前に caller が zero-arg callable を事前結線できない。
  readiness barrier は「`tg.create_task(...)` が gateway task の初回ステップを
  `call_soon` で先にスケジュール → 直後の `await asyncio.sleep(0)` が自分の継続を
  それより後にスケジュール」という asyncio 単一スレッド FIFO レディキューの
  決定的順序保証で実現（実ソケット bind 待ちではなく、construction-only スコープの
  honest なスケジューリング順序保証）。駆動完了で serve task を cancel、
  `contextlib.suppress(asyncio.CancelledError)` で shutdown-cancel のみ吸収し、
  真の例外は `ExceptionGroup` として伝播する（負例テストで確認）。

**AC6 の保証方法**: `run_society_live_loop` が `run_society_loop` に渡す
`on_runtime_ready` フックは、受け取った `WorldRuntime` を **1 回だけ** 自分の
`runtime_box` に append し、その**同一オブジェクト**を `SocietyLiveRunResult.runtime`
として返す。`supervise_society_live_loop` はさらにその同一 runtime を
`make_app(runtime=runtime, ...)` にそのまま渡す。第二の `WorldRuntime` /
`CognitionCycle` 構築箇所はコード上どこにも存在しない
（`build_society_live_world` は runtime を作らず、`supervise_society_live_loop`
も自前で構築しない）。`test_gateway_and_driver_share_same_runtime_instance` が
`app.state.runtime is result.runtime` を `is` 比較で直接検証。
