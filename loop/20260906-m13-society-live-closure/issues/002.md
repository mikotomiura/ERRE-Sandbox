# Issue 002: SocietyInboundRouter（inbound 摂動を N 体へ縦に通す）
verify_level: recheck

## Goal
Godot からの bounded 摂動（`InboundSink` に溜まる `WorldPerturbationMsg`）を、
**狙った agent の `PerceptionEvent`** として `run_society_loop` に渡すための router を新設する。
society.py は**無改変**（既存 public kwarg `observation_factories` だけで達成する）。

## Background
- `run_society_loop` は window ごとに `for agent_id in sorted_agent_ids: for obs in
  obs_factories[agent_id](cognition_tick): world.inject_observation(agent_id, obs)` を回す
  （society.py:1381-1387）。per-agent factory は **window ごとに sorted 順で 1 回ずつ**呼ばれる。
- **Codex M-1**: 「最初に呼ばれた factory が drain する」は隠れた順序依存。
  **`begin_window(tick)` 相当の idempotent drain coordinator** を router 内部に持ち、
  各 factory は bucket を読むだけにする。
- **Codex M-2**: ledger を `pushed` / `dropped`(overflow) / `drained` / `injected` /
  `rejected`(unknown target) の **5 状態に分離**。到達性の母集団は **injected のみ**。
- **決定論**: `world_perturbation_to_perception` の返す `PerceptionEvent.wall_clock` は
  `default_factory=_utc_now` で非決定（inbound.py）。**router 側で record-mode clock に pin** する
  （`inbound.py` の純関数写像は無改変のまま使う）。
- 摂動計画も in-process 合成なので `sent_at` を pin する（I7 前例）。

## Scope
### In
- 新規 `SocietyInboundRouter`:
  - `begin_window(tick)` — idempotent（同一 tick で複数回呼ばれても drain は 1 回）。
    `InboundSink.drain(max_n)` を bounded に 1 回だけ呼び、`target_agent_id` でバケツ分けする。
  - `observation_factories(agent_ids) -> Mapping[str, Callable[[int], Sequence[Observation]]]` —
    各 factory は「`begin_window(tick)` を呼んでから自分の bucket を読む」だけ。
  - 登録済み agent_id 集合を持ち、**unknown target は注入せず `rejected` へ**。
  - inbound 由来 observation の `wall_clock` を record-mode clock に pin。
  - 5 分割 ledger（`pushed` / `dropped` / `drained` / `injected` / `rejected`）。
    `injected` は `(agent_tick, correlation_id, msg, observation)` を保持し、I4 の到達性 witness と
    I6 の `ledger_observation_factories` の両方が読む一次資料になる。
- 事前登録の摂動計画 builder（純関数、N=3 × 12 window = 36 通、`sent_at` pin、
  `live_loop_perturbation_plan` の N 体版）。
### Out
- 閉包 root / supervisor（I3）、witness（I4/I5）、Plane G（I6）。
- 実 Godot からの送信（Out。Python 側の契約のみ）。

## Acceptance Criteria（AC↔test）
- AC1: `begin_window(tick)` は idempotent — 同一 tick で N 回呼んでも `drain` は 1 回だけ、
  bucket 内容は不変（Codex M-1）
  → `test_society_live_loop.py::test_inbound_router_drains_once_per_window`
- AC2: 摂動が `target_agent_id` の bucket にのみ入り、他 agent の factory は空を返す
  → `test_society_live_loop.py::test_inbound_router_buckets_by_target_agent`
- AC3: 未登録 agent_id 宛は **注入されず** `rejected` に入る（`injected` に現れない）
  → `test_society_live_loop.py::test_inbound_router_rejects_unknown_target`
- AC4: ledger が `pushed` / `dropped` / `drained` / `injected` / `rejected` に分離され、
  **overflow の負例**（`maxsize` を小さくして drop-oldest を起こす）で `dropped` が非零になり、
  drop された correlation-id は `injected` に現れない（Codex M-2）
  → `test_society_live_loop.py::test_inbound_router_ledger_five_way_split`
- AC5: inbound 由来 `PerceptionEvent.wall_clock` が pin 値で固定（2 回構築して byte 一致）
  → `test_society_live_loop.py::test_inbound_observation_wall_clock_pinned`
- AC6: 摂動計画が純関数（同一引数で 2 回 build して byte 一致、`sent_at` も一致）
  → `test_society_live_loop.py::test_perturbation_plan_is_pure`
- AC7: FIFO 順が保たれる（push 順 = drain 順 = bucket 内順）
  → `test_society_live_loop.py::test_inbound_router_preserves_fifo_order`

### I3 への申し送り

- **`observation_factories` の受け渡し**: I3 の `build_society_live_world` /
  `run_society_live_loop` は `SocietyInboundRouter(sink, agent_ids=
  SOCIETY_LIVE_AGENT_IDS)` を 1 個構築し、
  `router.observation_factories(SOCIETY_LIVE_AGENT_IDS)` の返り値をそのまま
  `run_society_loop(observation_factories=...)` に渡せばよい（`society.py` は無改変）。
  `sink` のライフタイムは router と同じスコープで管理すること（router は sink を
  保持するだけで所有権は取らない）。
- **ledger の読み方**: `router.ledger` は毎回フレッシュな
  `SocietyInboundLedger` スナップショットを返す（`dropped` は都度 live 読み、他は
  蓄積コピー）。I4 の到達性 witness は `ledger.injected`
  （`SocietyInjectedPerturbation` の列）を一次資料として読むこと —
  `ledger.dropped` / `ledger.rejected` は明示的に**到達性の母集団に含めない**
  （Codex M-2、design-final.md §6 W-N1）。I6 の `ledger_observation_factories` も
  同じ `injected` タプルから `by_tick` 相当を再構築できる（`live_loop.
  LiveLoopCaptureResult.observation_factory()` と同型の再構築が可能な形）。
- **`society_live_loop_perturbation_plan()`** は既定引数だけで sealed 値
  （3 agent × 12 window = 36 通）を返す。I3 が実際に `InboundSink` へ push する際は
  この関数の戻り値をそのまま `sink.push(msg)` で全件投入すればよい（push 順は
  window-major/agent-minor なので、そのまま FIFO 順で drain される）。
- **未使用のまま残した設計余地**: `DEFAULT_MAX_DRAIN_PER_TICK = 8` は
  `live_loop.py` と同値・同根拠だが本モジュール内で独立定義（import 結合を避けるため）。
  I3 が異なる drain 上限を必要とする場合は `SocietyInboundRouter(...,
  max_drain_per_tick=...)` で上書き可能。
