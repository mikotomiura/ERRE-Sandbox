# Issue 006: W-N4 Plane G — 無改変 `run_society_loop` への replay byte-parity + request conformance
verify_level: recheck

## Goal
live capture（Plane L）を **無改変の `run_society_loop`** へ replay して
`ecl_trace_checksum` / `event_log_checksum` の **byte-parity** を取り、
さらに **replay 側 spy** で prompt drift を検出する（Codex H-4）。

## Background
- **replay 時 `RecordReplayChatClient._used` は commit 済み call**（loop.py:230）。
  よって knob-on capture を **knob-off の無改変 `run_society_loop`** へ replay しても
  checksum は一致する（knob は sampling のみ変調、trajectory を変えない）。
- 逆に **prompt 一致は恒真になってしまう**（committed prompt をそのまま持つ）ので、
  prompt drift の検出には **replay 側で実際に再構成された prompt を記録する spy** が要る
  （I7 の `RequestConformance*` idiom の N 体版）。
- **Codex H-4**: 照合対象は `(agent_id, window, system_prompt, user_prompt)` と embedding request。
  **`sampling` は明示除外**（knob-on capture を knob-off replay するため一致しない）。
  knob-on 側 sampling の pin は既存 `two_phase_firing_summary` の `record_knob_on_pinned` で annotation。
- **Codex M-3**: byte-parity は **scripted in-process perturbation に限定**。
  実 Godot / WS 到着時刻 / LLM latency は外部非決定源で replay 対象外。
  「wall-clock real-time live session ではない」境界を明記する。
- float は 6 桁量子化。**生 serialized 埋め込み文字列（`model_dump_json`）は素通りする**ので
  projection 境界で再量子化（PR #55/#76 の轍、`feedback_golden_crossplatform_float_drift`）。
