# Issue 006: Ocsai 縦スライス — jsonl から verdict まで (ARM-C 込み)
verify_level: recheck

## Goal

2 本目の独立コーパスを端から端まで通す。`main2` の train+val+test を**この順で連結** →
`AUT Prompt:<object>\nResponse:<text>\nScore:` を parse → 二値化 (encoded 10 / ≥40) →
行 index parity split → anchor ARM-A / ARM-B / **ARM-C (A1∪A2)** → 同じラダー →
`results/external-audit.json` に Ocsai の verdict が出る。

## Background

Ocsai は Cambridge に無い**頻度構造**を持つ (正規化後の出現 ≥2 が brick 174 / paperclip 80)
ので、内部レシピ第 2 段 (高頻度 augmentation) の外部対応物 = **ARM-C** が構成できる唯一の
コーパス。**verdict は ARM-A (両コーパス共通構造・capped-30 seeded 抽出) から出す** —
アーム構造が違うと「2 本中 k 本」の k が意味を失う (DA-G1-13 / DA-G1-18)。

## Scope

### In
- Ocsai adapter (`jsonl`)。連結順は `train` → `val` → `test` で固定 (DA-G1-14)
- ARM-C = A1 ∪ A2 を dedupe 後 30 件。A2 = `split0` の正規化文字列の**出現回数上位、最低支持 ≥2**
- 物体の扱い (Codex HIGH-2 で凍結): **primary = 全 21 物体** / **sensitivity = 内部 battery と
  重なる 4 物体** (brick/paperclip/bottle/shoe)。物体を落とす条件は
  **`|R_o| < N_R_MIN` または gold クラス不足のみ**。落とした物体は件数つきで surface する
- **ARM-X (source-crossed、`paperclip` のみ)** — anchor = **Cambridge** paperclip の gold-common
  プール / gold と採点項目 = **Ocsai** paperclip。**別研究・別 rater・別被験者**なので
  **provenance 独立が本当に成立する唯一のアーム** (Codex HIGH-1)。verdict は出さないが
  結果は必ず出力する
- Ocsai 未取得時は `"status": "source_unavailable"` を記録し、**Cambridge 側の verdict は出す**
