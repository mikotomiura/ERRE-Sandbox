# 概要 (Summary)

ERRE-Sandbox は、ループの内側でローカル言語モデルを動かす身体化マルチエージェント
シミュレーションのための Python 装置である。その設計は状態を二つの平面に分離する。
物理・記憶幾何・乱数ストリーム・時計・識別子・スケジューラ順序は *simulation plane* に
pin され、モデル呼び出しはすべて *model-call plane* で記録・再生される。

この分離のもとで、実行は OS を跨いで byte-exact になる。ここでの byte-exact とは、
文書化された正準化——浮動小数点値を 6 桁へ量子化する——のもとで、
出力される全 artifact が同一のバイト列に再レンダリングされることを意味する。
**生の IEEE-754 の結果が一致するという意味ではない。** 量子幅は趣味ではなく実測に対して
選ばれている。凍結された三角関数経路で観測された libm 間の最大 drift は 8.88e-16 であり、
これは概ね 1 ULP で非増幅、丸めを決める 5e-7 の量子半幅より 6 桁小さい。

実在の `qwen3:8b` が駆動した 3 エージェントの封印実行は、Windows と Linux の双方で同一の
ハッシュへ再レンダリングされ、公開 CI が全 pull request でこれを検査している。

# なぜ必要か (Statement of need)

言語モデルをシミュレーションのループに入れると、再現性が失われる。再現の契約が無ければ、
結果についての意見の相違を「解析が誤っている」と「実行そのものが違っていた」に
切り分けられない。**決定性はこの種のシステムを監査するための前提条件であって、
仕上げの装飾ではない。** LLM 駆動のエージェント社会のフレームワーク
[@park2023generative; @al2024projectsid] はモデルを不透明なサービスとして扱い、
そうした契約を提供していない。

障害は、非決定性が**互いに無関係な二方向から同時に入り込む**ことにある。一方はモデル呼び出し
そのもの。他方はその周囲のすべて——C ランタイム間の浮動小数点差、ハッシュ種に依存する反復順序、
実時計、UUID、そして 1 ステップ内でエージェントがスケジュールされる順序である。
前者だけを pin しても実行は依然として乖離し、後者だけを pin してもモデルは自由に乖離する。
ERRE-Sandbox は**両方を同時に pin する**ために存在し、かつその主張を
**GPU も言語モデルも持たない読者が自分で検査できる**形にするために存在する。

# 分野の現状 (State of the field)

LLM エージェントの決定論的 replay は新しくない。**本稿はそこに新規性を主張しない。**
agrepl [@mudasiru2026agrepl] は man-in-the-middle プロキシによって外部とのやり取りを
transport 層で傍受し、5 種のワークロード・250 インスタンスにわたり replay fidelity F = 1.0 を
報告している。AgentRR [@feng2025agentrr] もエージェント実行を記録・再生するが、目的が異なる——
決定性の検証ではなく**経験の再利用**である。「record and replay」という語は、
この文献群の中で少なくとも二つの別々の目標を指している。

開いたままなのは、**プロキシが届かない層**である。

|  | agrepl [@mudasiru2026agrepl] | ERRE-Sandbox |
| --- | --- | --- |
| シミュレーション側の状態（物理・RNG・時計・識別子・スケジューラ順序） | 扱っていない。プロキシは外部呼び出しを傍受するのみで、シミュレーション自身を pin しない | 第一級の平面として pin し checksum を取る |
| OS を跨いだ byte 一致 | 主張していない。fidelity は単一の隔離環境内で報告されている | Windows で作成した bundle が Linux 上でも、**著者機とは別個体の** Windows 上でも同一に再レンダリングされる |
| 正準化の数値的正当化 | 対象外 | 実測した libm 間 drift に対して量子幅を選択 |

: 最も近い先行システムに対する delta。

# ソフトウェア設計 (Software design)

設計上の問いは**どこで切るか**であった——シミュレーションが決めることと、モデルが決めることの
あいだで切り、それぞれを別々の機構で pin する。

| simulation plane が pin するもの | model-call plane が pin するもの |
| --- | --- |
| 物理ステップと記憶幾何。SHA-512 で seed される名前付き RNG substream（`PYTHONHASHSEED` 非依存）。凍結された retrieval clock。tick から導出される記憶 ID とタイムスタンプ。retrieval の同点に対する全順序。envelope の送信時刻。記録された環境 pin | すべての action モデル呼び出しを outcome tag（`ok` / `unparseable` / `raised`）つきで記録するので**失敗経路も再生される**。replay は記録済み応答を注入しモデルを呼ばない。記録中は reflection を無効化し、モデル側の第 2 の非決定源を閉じる |

: 各平面が pin するもの。列挙はコード内の `DETERMINISM_CHECKLIST` および
`M2_NBODY_DETERMINISM_CHECKLIST` で維持されている。

エージェントが複数になると、単一エージェントには対応物のない pin が 1 つ増える——
認知ウィンドウ内でエージェントがステップされる順序である。これはエージェント識別子の
ソート順で固定され、`asyncio.gather` による fan-out なしに厳密逐次で実行され、
実行の環境 pin に `society_cognition_step_order` として記録され、checksum が取られる。
`uuid4` 由来の対話識別子は、同じ扉から非決定性を再導入するため除去した。
**ここで分離が対価を回収する。** transport 層の replay は**発生したリクエスト列は記録できる**が、
それを生み出した**シミュレーション内部の順序を pin / 監査 / checksum しない**。
**この論証は 2 体以上でのみ成立する**——単一エージェントでは可能な順序が 1 通りしかなく、
pin すべきものが無い。

正準化は二平面の継ぎ目である。artifact は canonical JSON——キーのソート、コンパクトな区切り、
`ensure_ascii=False`、そして**非有限値は黙ってハッシュせず例外を送出する**——として直列化され、
すべての float は 6 桁へ量子化される。この代償は二度払った。埋め込まれた JSON 文字列の内側で
**既に直列化済みの float は量子化器を素通りする**ため、射影境界で再量子化している。
この穴は「塞がったと仮定する」のではなく**文書化してある**。

量子幅の正当化が要るのは、**背後の問題が既知かつ未解決**だからである。C++ 委員会文書 P3375R3 は
「C++ は再現可能なプログラミングを支援しない。実際、規格は浮動小数点の挙動を一切規定していない」
と明言し [@davidson2025p3375]、同一のソースがコンパイラによって異なる値を出す実例を示している。
ここでの応答はそれを**解決する**ことではなく**境界づける**ことである。実測 drift は 8.88e-16、
量子半幅は 5e-7 であり、6 桁の余裕をもって両プラットフォームが同一に丸める。
トレードオフは実在する——6 桁はミクロン未満の空間解像度を捨てる——ので、
**読者が自分の用途に同じ境界が適するかを判断できるよう明示してある。**

# 研究上の意義 (Research impact statement)

装置は、3 エージェント × 12 認知ウィンドウ × 各 20 物理 tick の封印実行によって駆動されている。
実在の `qwen3:8b` と実在の埋め込みモデルが、固定 seed のもとで 36 回のモデル呼び出しと
112 回の埋め込み呼び出しを行った。**ハーネスは明示的な批准なしに支出を拒否する。**
記録済みレコードの replay は全 artifact の SHA-256 を再現し、
**全 replay チャネルでモデル呼び出しは 0 回**、リクエスト整合はモデル呼び出し 36/36、
埋め込み 112/112 で成立した。

公開 CI は同じ検証を全 pull request で `ubuntu-latest` と `windows-latest` の双方に対して実行し、
Windows runner は著者機とは別個体である。**CI が強制しているのは replay-verify であって
bake ではない**——bundle を再生成する job は存在せず、これらのバイト列が Windows 上で
生成されたという主張は、CI の witness ではなく **manifest の環境 pin に依拠した著者の申告**である。

読者は replay 側だけを自力で閉じられる。必要なのは runtime 依存のみの 1 コマンドで、
テストフレームワークも機械学習の extras も GPU も言語モデルも要らない。
**これは live bake の再現ではない。** 価値はより狭く、かつ検査可能である——
replay は**モデル呼び出し 0 回のまま**出力を再生成し、再生成されたバイト列はリポジトリに
commit されたハッシュと一致する。非決定性スキャナも同じ基準に置かれている。
単一のテストが negative fixture と clean fixture を同時に閉じるので、
**検出器が恒真でないことが示されている**——@shulepov2026mutation が再現性 safeguard について
実証的に記録している失敗様式である。

*研究での利用。* 本装置の上で事前登録された監査が 2 本実行されている
（@otterson2026adversarial が記述するのと同型の frozen-parameter 統制）。
**いずれも null ないし非支持の結果を返し**、その artifact は公開リポジトリに commit されている。

*開発履歴。* 公開 commit 履歴は構造的に短い。公開前に研究用 scaffolding を剥がすため、
リポジトリは 2026-05-31 に単一のクリーンコミットで再作成され、それ以前の履歴は破棄された。
以降 293 commit が積み上がっている（2026-09-12 実測）。開発自体はさらに遡る。
追跡下の文書は 2026-04-21 まで日付の連鎖を持ち、2026-04-30 の 117–127 番の merge 済
pull request を参照している——**現在のリポジトリが共有していない番号体系**である。

# 限界 (Limitations)

凍結された計測装置の不変性は**規律のみによって**維持されている。CI の diff gate も
pin されたハッシュのテストも存在しない。静的な egress 検査は**意図的に弱い**バックストップであり、
主たる境界は behavioural test である。これは単一のコードベースであり、単一のモデル族で、
単一の開発者によって動かされている。

**過大に読まれやすい境界が二つあるので繰り返す。** CI が強制するのは replay-verify であって
bake ではなく、bake は著者機の上に留まる。そして CI runner はクリーンな機械ではあるが
**第三者ではない**——機械的に示されているのは「手順が著者機でない機械で通る」ことであって、
「独立した人間がそれを実行した」ことではない。replay はネットワーク接続を一切開かないが、
依存のインストールにはどんなインストールとも同様に package index が要る。

Godot 側の再現はこのすべての外側にある。実エンジンを通した end-to-end のデモは**行っていない**。
これらのローカル headless テスト（`SocietyReplayViewer.gd` を `--headless` で実行）は
Godot バイナリが無ければ self-skip し（ここでは 4.6.2、`GODOT_BIN` で解決）、したがって
CI では走らない。比較対象は生のバイト列ではなく**文書化された canonical placement** であり、
exercise するのは placement の import と export のみで、live な認知・埋め込み・
エンジン側物理は exercise しない。加えて、未解決の欠陥により
**描画されるゾーン配置が単一ゾーンへ潰れる**。

二相サンプリング制御は封印実行では**発火しなかった**。適格な tick が 1 つも生じなかった。
これは事前登録上の正当な結果であり、発火させるための再実行は行っておらず、
**本稿はいかなる行動上の帰結も主張しない。**

予期ではなく実地で得た戒めが 1 つある。初期の Windows CI 実行が落ちたのは、lockfile が
リポジトリの行末 pin の被覆から漏れており、その image が異なる行末で checkout した結果、
pin されたハッシュが変わったためである——**著者機と Linux runner はいずれも LF なので、
この 2 つだけでは永久に観測できなかった。**

# AI 利用の開示 (AI usage disclosure)

本プロジェクトは**相当量の AI 支援のもとで開発されており、ここに全面的に開示する。**
Claude（Anthropic。Claude Code 経由で Opus / Sonnet / Haiku の各モデル）を実装・
リファクタリング・テストの足場・文書化、および**本稿本文の起草**に用いた。
OpenAI Codex（`gpt-5.5`）を独立した設計・コードレビューに用いた。
支援の事実はここでの主張ではなく**公開記録に現れている**——
公開 293 commit のうち 254 件が、使用モデル名を記した `Co-Authored-By` trailer を持つ
（2026-09-12 実測）。

**AI 支援による出力はすべて人間の著者がレビュー・編集・検証し、中核的な設計判断は人間が下した**
——二平面分離、正準化の規則と量子幅、本稿の全主張の射程、そして投稿先とタイトルを含む。
検証は自己申告ではない。replay-verify に関する主張はリポジトリ自身のテストと公開 CI によって
強制されており、その guard 自体も mutation によって検査されている。
Windows での bake の来歴は、上に述べたとおり **manifest に裏づけられた著者の申告**のままである。
